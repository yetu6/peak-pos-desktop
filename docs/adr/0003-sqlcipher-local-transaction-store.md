# ADR 0003: SQLCipher local transaction store

- Status: Accepted for Phase 3
- Date: 2026-09-03
- Security review gate: required before offline selling is enabled

## Context

Peak POS V1 requires durable offline order and cash evidence. The canonical specification prohibits browser persistence as authority, React-owned SQL, plaintext production fallback, and homemade database encryption. The terminal must package a reproducible encrypted SQLite implementation across supported desktop targets and fail closed when its database key is unavailable or invalid.

## Decision

The Rust transaction core uses `rusqlite` 0.40.2 with its `bundled-sqlcipher-vendored-openssl` feature. The resolved native chain is:

| Component | Pinned/resolved version | Provenance |
| --- | --- | --- |
| `rusqlite` | 0.40.2 | crates.io release, MIT |
| `libsqlite3-sys` | 0.38.2 | crates.io release consumed by rusqlite |
| SQLCipher Community Edition | 4.14.0 community | amalgamation embedded in `libsqlite3-sys` 0.38.2 |
| SQLite baseline | 3.51.3 | embedded SQLCipher amalgamation header |
| OpenSSL source provider | 3.6.3 through `openssl-src` 300.6.1+3.6.3 | vendored source build, Apache-2.0 |

Cargo compiles and statically links the embedded SQLCipher amalgamation and vendored OpenSSL. Peak does not depend on an unknown system SQLite or dynamically discovered SQLCipher library. `Cargo.lock` is part of the reproducible build boundary.

The database key is 256 bits generated by the operating-system CSPRNG. Rust stores it only in a versioned envelope in the operating-system keyring and applies it as a raw SQLCipher key before any schema access. The envelope contains a domain-separated key check so malformed or damaged secure-store records fail before database access. Temporary key bytes are zeroized.

Production behavior is fail closed:

- a new database may be created only after its key envelope is durably stored;
- an existing database with no readable envelope is preserved and classified `MISSING_KEY` or `SECURE_STORE_UNAVAILABLE`;
- a malformed envelope is `INVALID_KEY_ENVELOPE`;
- a valid envelope that cannot decrypt the existing database is `KEY_MISMATCH`;
- a decryptable database that fails SQLCipher or SQLite integrity checks is `CORRUPTION` or `INTEGRITY_FAILURE`;
- migration and disk-full failures are separately classified;
- no failure path silently deletes, replaces, or opens the database as plaintext.

Connections enable SQLCipher memory security, foreign keys, WAL, `synchronous=FULL`, secure delete, a bounded busy timeout, and untrusted-schema restrictions. Rust owns connection and migration lifetime. The only Phase 3 IPC surface is a redacted health/status command; there is no generic query command.

## Rotation and recovery

Rotation uses a versioned current/next envelope and an encrypted owner-only recovery copy. The workflow checkpoints WAL, writes the protected copy, records `PREPARED`, rekeys under exclusive access, reopens with the next key, verifies both cipher and database integrity, promotes the next envelope, and then removes the recovery copy. Restart recovery accepts either the healthy current-key or next-key state and completes promotion without discarding evidence. If neither opens, Peak preserves both files and fails closed for management-led recovery.

Key loss recovery is terminal reprovisioning, not key reconstruction. Unreconciled local evidence may be unrecoverable. The application must disclose that consequence and must not silently reuse the old terminal identity or sequence epoch.

## Packaging and release gates

Linux x86_64 is verified in this Phase 3 workspace. Windows x86_64 and macOS arm64/x86_64 require clean CI builds, native launch, encrypted-open/restart/rotation tests, signing/notarization validation, and license-notice inclusion before those artifacts are releasable. Unsupported or unverified targets fail the release gate.

Every dependency update must repeat runtime `PRAGMA cipher_version`, encryption-at-rest, wrong-key, integrity, migration, rotation-interruption, and packaged-Tauri tests. SQLCipher 4.17.0 is newer than the currently released rusqlite bundle; upgrading to it is required once a reviewed rusqlite/libsqlite3-sys release embeds it or a separately reviewed vendor package is adopted. Peak will not replace this reproducible release dependency with an unreviewed git snapshot merely to change the version number.

SQLCipher Community Edition requires reproduction of its BSD-style notice in distributed materials. [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md) is therefore a required bundle artifact. OpenSSL notices must also remain available to users.

## Threat boundary

SQLCipher protects database contents at rest and raises the cost of offline inspection or modification without the key. It does not defeat a fully compromised OS/root environment that can steal the device key, inspect process memory, or roll back all local files and secure anchors. Sequence/hash-chain reconciliation and operational controls address detection and containment without claiming prevention of complete terminal compromise.

## Consequences

- Native builds take longer because SQLCipher and OpenSSL compile from pinned source.
- The application can remain visibly running when secure storage fails, but the local store is unhealthy and later offline mutations must remain disabled.
- Platform CI and legal-attribution checks are release blockers, not optional packaging polish.

## Phase 3 verification evidence

The Linux x86_64 gate executed on 2026-09-03 with Rust 1.97.1. Runtime provenance tests reported `4.14.0 community` from `PRAGMA cipher_version` and SQLite `3.51.3`. The suite verified encryption at rest, unkeyed/wrong-key rejection, missing and malformed key failure without file replacement, schema migration and constraints, owner-only permissions, integrity checks, rekey, and restart recovery after interruption between SQLCipher rekey and secure-store promotion. The real Tauri binary launched under Xvfb and remained running with the production startup-managed store boundary. Windows and macOS remain explicitly unverified release gates under the packaging section above.
