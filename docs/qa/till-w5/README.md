# W5: papers and print recovery

Kitchen/bar fulfilment, layouts, optional branding and durable recovery keep the existing order, payment, refund and permission boundaries. Merge W1–W4 first, then W5 backend [yetu6/fbc-peak#306](https://github.com/yetu6/fbc-peak/pull/306), hotel [#152](https://github.com/yetu6/peak-hospitality-web/pull/152), then this Till PR. W6 prepares version 0.1.4; Claude owns reconciliation, merging, release, deployment and real-till checks.

The owner's latest instruction supersedes the earlier advertising omission: **Powered by Yetu-FBC** appears at the foot of every printed paper, centred and bold on thermal printers, with a ruled centred signature on system-printer text. The preview adds visual emphasis without changing its decoded text. Bills keep the property's identity and transaction references.

## Behaviour and settings

- Prepared lines appear under MAKE, Picked under HAND OVER first. Direct lines produce no production paper; a Direct-only round can still be submitted. Default fulfilment remains PREPARED; product overrides category. Every sold line still moves stock.
- Quantity bold and large settings default true. Copies per station default 1, bounded to 1–3; additional configured production copies are marked COPY within one durable attempt. New printer selections prefer 80 mm; existing missing-width choices retain 58 mm.
- Bill logo is per printer, default off, from property branding. The Till converts to monochrome GS v 0 (576/384 dots), caches up to eight images/5 MiB by property/checksum/width, and retains a text-only fallback. The business name always prints. No logo on kitchen/bar papers.
- Automatic customer printing following payment remains OFF. There is no new automatic-post-payment setting. Existing automatic kitchen/bar submission dispatch, manual paid-bill copies and authorized refund slips remain.
- Copies preserve the original transaction document and reference chain. Neither printing nor recovery creates a sale, payment, refund or fiscal transaction. Copy printing never pulses the drawer.
- Signed previews bind caller, order version, paper kind, document contents and time. Server TTL is `YETU_POS_PAPER_PREVIEW_TTL`, default 300 seconds. Expired tokens remain attached so the server refuses them; they never silently become unbound requests. The Till freezes the exact route, width, prepared bytes and logo at confirmation.
- Failed jobs must be claimed again under their next attempt key. Accepted native evidence retries only the server acknowledgement. Unknown delivery never automatically resends. Status shows waiting papers; an operator can explicitly confirm a physically observed paper, or request a marked copy from its order. A session change during a claim/probe stops printing and acknowledgements under the new session.

The encrypted native journal is schema 6, upgrading existing schema 4 through W4's schema 5. It binds scope, backend job/attempt, route and payload. A durable UNKNOWN record precedes transport. Known pre-write failure permits a corrected-route retry; partial write/process interruption requires manual inspection. The named capacity is 100,000 attempts, fail closed rather than evicting duplicate-protection evidence. See [native evidence](../w5-native-print-journal.md).

## Limits and reconciliation

A submitted order/round and its physical print result remain separate, as in the working system. A printer failure leaves a visible failed/claimed job; it does not undo an already submitted order, stock movement or payment. TCP/spooler acceptance cannot prove paper emerged. The existing no-paper station choice leaves jobs for a printing Till and does not discard them.

The signed offline catalogue schema is unchanged: offline cash sales retain their existing reconciliation behaviour and do not acquire a new automatic production-print path. Advisory online settings do not become offline financial authority.

No merge, tag, release, deployment, production writes or live credentials were used. Physical 58/80 mm printers, Windows spooler hardware, touch operation, network interruptions on the real Till and owner acceptance remain Claude/owner checks in W6.
